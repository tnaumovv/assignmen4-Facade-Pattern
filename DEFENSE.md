# Краткая подготовка к защите

## Что сказать в начале

Я выбрал Option A — Media/File Conversion Facade. Клиент вызывает один метод `convert(fileName, targetFormat)`. Фасад создаёт четыре подсистемы и вызывает их в нужном порядке. Данные конвертации симулируются, но каждый шаг выполняет свою работу: проверяет имя, выбирает настройки, ограничивает bitrate или пересчитывает размер.

## Порядок демонстрации

1. Покажи `Main`: он создаёт только `MediaConversionFacade` и получает `ConversionResult`.
2. Открой `MediaConversionFacade`: `MetadataReader → CodecFactory → BitrateReader → AudioMixer`.
3. Запусти demo командами из README.
4. Объясни результат: `(2500 + 160) × 120 / 8 = 39900 kB`.
5. Покажи проверки некорректного ввода через `AcceptanceChecks`.

## Короткие ответы

- **Что такое Facade?** Структурный паттерн, который даёт простой общий интерфейс к нескольким подсистемам.
- **Что скрывает этот фасад?** Создание помощников, порядок вызовов и передачу промежуточных данных.
- **Подсистемы знают о фасаде?** Нет. В их коде нет ссылки на `MediaConversionFacade`.
- **Можно вызвать подсистемы напрямую?** Да: классы и их методы публичные. Это свойство Facade из лекции.
- **Почему стрелки пунктирные?** Это dependencies — использование типов в методах. Помощники создаются локально; фасад не хранит их в полях. Стрелка направлена к используемому классу.
- **Почему используются records?** Они кратко описывают неизменяемые данные и автоматически дают accessors. `AudioMixer` возвращает новый результат.
- **Почему это проще для клиента?** Клиент передаёт два значения вместо самостоятельной координации четырёх объектов.
- **Facade и Adapter отличаются?** Facade упрощает доступ к подсистеме. Adapter согласует несовместимые интерфейсы.
- **CodecFactory — это отдельный обязательный паттерн?** Нет. Здесь это простой класс выбора настроек; задание демонстрирует Facade.
- **Программа конвертирует настоящее видео?** Нет. Она детерминированно симулирует преобразования метаданных и настроек, что разрешено в Option A.
